# Shape and material decisions

Reference: Apple HIG [Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons), [Icon Composer](https://developer.apple.com/icon-composer/), and WWDC25 [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) / [App icons](https://developer.apple.com/videos/play/wwdc2025/220/).

The sidebar uses native `NSGlassEffectView` where available, with vibrancy fallback. Web controls use an approximation of the material, rather than Apple's private Icon Composer rendering engine. Navigation and transient controls have the most transparent material. At the user's request, device tiles also use a restrained dark-glass finish: a high-opacity body for legibility, a continuous reflective edge, and a tint derived from the device's actual light output. Other active devices retain the neutral highlight.

`HomeCategoryDock` is shared by Home and category routes. It stays above the scrolling content with backdrop blur and an explicit selected state. Categories observe Home visibility, while the inventory and room pages retain their wider device scope. The unfiltered Home renders each room's device grid in a continuous vertical stream; scenes sort by room first and visible title second, with natural numeric order. Scene menus appear on hover, keyboard focus, or while open; touch devices retain a visible trigger.

The category layer uses three progressively masked blur bands, with horizontal scroll shadows on the picker itself. The native scroll physics are retained. Selected badges are brought into view with a smooth horizontal scroll, respecting reduced motion. The device stream uses TanStack Virtual to mount visible room/category sections plus one section of overscan. Measured heights and responsive grid estimates keep the page scrollbar stable; a focused or dragged section stays mounted. The stream shares the page's scroll container, so the floating categories and camera-first hierarchy remain intact.

The current connection model holds one home, so the sidebar has no redundant home switcher. Management links follow the rooms, and infrastructure areas follow physical rooms. Category navigation is neutral; actual light colors remain on device controls. Filter borders use the same edge token and concentric continuous corners. Device radii are shared by active and inactive states. Scene visibility always targets the scene entity itself, including Hue scenes registered under a shared bridge; device visibility excludes those scene entity IDs.

Home scene cards show room and title without an accessory count. Hue artwork reads each enabled bridge's diagnostics through the existing authenticated Home Assistant connection, for administrator accounts. Only the derived colors and dark-state flag stay in the in-memory snapshot. The scene is matched by bridge, room and scene name because diagnostic IDs may be redacted. Preview colors come from its configured Hue palette or light actions, including color temperatures, rather than the current state of its lamps. Ambiguous matches retain the neutral artwork. Reading previews never activates a scene.

Room grids rank everyday controls before passive telemetry and infrastructure. Explicit favorites lead, and saved drag placement takes precedence. Ordering uses device type and natural names, never power state or live use counts. Safety events use the attention surface. Quick controls learn from use when entering Home, then keep the current visit’s selection and positions stable. Compatible numbered lights in the same known room can share a local tile and controller; commands expand to their actual HA entity IDs. Common controls respect every member's capabilities and temperature range. Offline members stay visible in the group while commands address reachable members. Each group can be separated through its controller/context menu, and Settings can disable automatic grouping or reset the exceptions. Hidden items, search results and quick controls retain their individual presentation.

Camera cards display seconds since the last successfully loaded snapshot. Like the reference in `scrypted-tuya/bridge/apps/web/src/components/CameraCard.tsx`, snapshots refresh every ten seconds while the window is visible. Requests never overlap, failed refreshes retain the displayed frame and its age, and identical successfully refreshed image bytes renew the age without another decode. This is the age of the snapshot update, not a claim about when the camera originally captured the image.

`materials.css` owns shared continuous-corner tokens, inset radii, icon enclosure geometry, control glass and accessibility overrides. Circles and capsules retain round geometry. Native CSS `corner-shape: superellipse()` paints borders, shadows, clipping and focus outlines consistently; ordinary rounded corners remain the fallback.

Brand icons have separate background, enclosure rim and foreground layers. SVG lighting uses a blurred alpha height map and an eroded contour band, so highlights follow each foreground silhouette. It doesn't invert brand colors or apply a bright flat overlay to the whole image. The foreground receives a small shadow and, for neutral dark silhouettes in dark appearance, a light material gradient.

Source vectors remain vectors. Small analysis canvases are never reused as the final visible artwork; bitmap separation runs at source resolution, bounded to 1024 px. Matter and Thread use bundled vector marks, including the Matter Server alias, rather than enlarging server thumbnails. Other integrations request Home Assistant's `@2x` brand assets. Complex flattened images retain their original artwork; arbitrary semantic layers cannot be recovered reliably from a flattened bitmap.

Device mutations use a shared optimistic overlay over server facts. Every view receives the same predicted state and parameters, with a pending indicator. Commands for one target execute in click order; scenes share a queue. Authoritative events reconcile the overlay, including HA-normalized values linked by command context. Rejection, unavailability, timeout or a changed connection removes local intent without restoring superseded values. Buttons and unknown actions show progress without inventing outcomes.

Light prediction restores the last confirmed output, scoped to the connected home and persisted with a bounded local cache. Null off-state attributes do not erase color, brightness or temperature. Missing output can be recovered through read-only, batched HA history queries for the last day and then the preceding six days. Explicit command parameters win. Partial on-reports retain known output until the device reports new values; zero brightness remains authoritative.

Device and light-group sheets use a quiet frosted body with continuous corners, a reflective rim, contextual output glyphs and sticky glass navigation. The controller keeps usable inputs available during ordinary state updates. State surfaces cross-fade without moving hit targets, and accessibility preferences reduce motion, transparency and contrast effects. This is the web material approximation; the sidebar retains native Liquid Glass/vibrancy.

Tile illumination uses an unmasked color-fill layer below the content and a separate masked glass contour. The active wash and soft outer glow remain visible without hover. Power changes animate the fill, edge, icon and state label; the last output accent is retained through the fade to off. Dark tiles and the Home category dock use darker material bases while preserving the selected state. Reduced motion removes the movement and transitions.

Device loading feedback stays quiet for the first six seconds. Predicted state and parameters still update immediately. Tiles and controllers share the oldest unresolved command timestamp, including grouped members, so opening another view does not restart the delay. Completion or failure cancels the indicator.
