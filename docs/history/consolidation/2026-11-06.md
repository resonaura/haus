# NVR transport consolidation — 2026-11-06

## Accepted scope

P14.2.1 review and P14.2.3.1 are verified. P14.2.3 remains active: runtime composition/telemetry (P14.2.3.2), deployment/native/test assets and Node retirement (P14.2.3.3) are still pending.

## Changes

- Removed apps/node/lib/server.mjs, auth.mjs and http.mjs. Bootstrap, recovery and all Node test consumers now use the compiled public @haus/hub/nvr exports.
- NvrTransport owns the existing authenticated protocol. Focused camera, metadata, blob, status and reply handlers live in apps/hub/src/nvr/transport. Existing HMAC framing, nonce replay protection, grant lifetime, cursor/range behavior, camera ownership and response codes remain in place. Malformed signed JSON now returns invalid_json/400 without exposing its contents.
- NvrModule plugs the same transport into createNestApp({ nvr }) on the existing Hub HTTP server. Middleware runs before Nest body parsing, preserving the exact digest/upload bytes. This is exercised on one ephemeral listener alongside ordinary Hub API endpoints.
- The WebSocket adapter delegates RTSP upgrades before its default WebSocket handler; /api/live continues working. Validated adapter cache shapes replace the previous as-unknown-as casts. Unknown upgrades retain the platform adapter's rejection behavior.
- HomeKit media wire decoding validates unknown payloads into owned protocol contracts. Its minimal media-start payload is distinct from the full HAP controller request; existing controller types and media engines remain compatible.
- Transport shutdown rejects new work, aborts active responses, stops policy/relay/media users in order, drains requests and only then closes the recording index. Cleanup failures are collected rather than stopping remaining cleanup. The unfinished-upload test verifies released reservations, removal of partial data and preservation of an existing original before shutdown completes.
- Review found that the backup catalog changed memory before saving its JSON metadata. It now publishes a staged snapshot only after a synced atomic file replacement; failed catalog saves retain the prior view, queued writes recover, returned snapshots cannot mutate storage, and corrupt/partial saved metadata fails closed. Per-kind retention and restart tests cover the change. Errors deleting expired blobs after the catalog commit still surface; they do not roll back already committed metadata.
- RecordingIndex close is idempotent. WorkerStreams exposes its configured origin again, preserving the status contract that was lost during the earlier engine extraction.
