## Interoperability sources and limits

Use public plugin documentation and package metadata/type declarations only; do not use Scrypted server or SDK implementation source. No `@scrypted/server` or `@scrypted/sdk` runtime package is installed or vendored. Kitsune's implementation and its simulated-plugin fixtures are independently authored under GPL-3.0-only. Existing project-wide GPL-3.0-or-later licensing is not silently changed.

Public npm metadata checked on 2026-11-03 reports the standard RTSP, ONVIF, Reolink, Hikvision, Amcrest and UniFi Protect packages. `@scrypted/dahua` and `@resonaura/scrypted-tuya` return 404: Dahua must route through the documented Amcrest family adapter, and the proposed Tuya fork must not be advertised as installable. Tapo/Ring metadata does not provide a license field; surface this in installation receipts rather than inventing a license or bundling their code.

Published plugin metadata includes development `file:../../sdk` / `file:../../common` dependencies. The runtime must consume the packaged plugin artifact, skip the intercepted SDK dependency, and resolve only actual external runtime dependencies; it must not run npm lifecycle scripts or interpret arbitrary local paths.

Kitsune is a versioned compatibility implementation, not a promise that every unmodified plugin already works. Unknown SDK calls generate bounded structured diagnostics and safe chainable fallbacks; missing camera/media capabilities never create fake frames or successful device commands. Physical vendor acceptance follows actual plugin compatibility, and cannot be inferred from simulated lifecycle tests.
